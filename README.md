# Магазин номеров: бот, мини-апп, админка

Telegram-бот продажи номеров (Telegram-аккаунты из категории `/telegram` на LZT Market),
публичный сайт, Mini App внутри Telegram и отдельная админка.

## Стек

| Слой | Чем |
|---|---|
| Боты (основной и поддержка) | aiogram 3 |
| Админка, мини-апп, вебхуки | FastAPI + Jinja2, серверный рендер |
| База | SQLAlchemy 2 async + Alembic; sqlite локально, Postgres в проде |
| Источник номеров | LZT Market API (`https://prod-api.lzt.market`) |
| Оплата | Crypto Bot, xRocket, Platega (карта/СБП) |
| Карточка отзыва | Pillow — рисуется по шаблону, отправляется картинкой |
| Очистка аккаунта | Telethon + Auth Key/DC ID, `StringSession` только в памяти |

Проверено на Python 3.14.3 / Windows. Версии в `requirements.txt` зафиксированы:
старые не двигаем, новое добавляем отдельной строкой.

## Установка

```bat
scripts\setup.cmd
```

Скрипт создаёт `.venv`, ставит зависимости, копирует `.env.example` в `.env`,
применяет миграции и заводит настройки по умолчанию.

Дальше в `.env` нужны токены: `BOT_TOKEN`, `SUPPORT_BOT_TOKEN`, `LZT_TOKEN`
(берётся на https://lolz.live/account/api), а для доступных способов оплаты — токены
провайдеров. Контракт интеграции LZT сверяйте с обязательной документацией
[lolzteam-py: Market API sections](https://github.com/medovi40k/lolzteam-py#market-api-sections).


Если с сервера заблокирован `api.telegram.org` (типичная ситуация в РФ),
впишите `BOT_PROXY`. Понимаются оба формата записи: `socks5://user:pass@host:1080`
и `socks5://host:1080:user:pass` — как выдают продавцы прокси. Схема по умолчанию
socks5, поддерживаются socks5/socks4/http. Через прокси пойдут оба бота.
Проверить: `python -m app.tools.tg_check` — печатает, живо ли соединение и
совпадают ли юзернеймы ботов с токенами.

## Запуск бота

```bat
scripts\bot.cmd
```

Пять разделов: магазин, пополнить баланс, профиль, заработать, поддержка.
Нижняя клавиатура даёт разделы в один тап из любого места, внутри раздела —
inline-кнопки с правкой сообщения на месте.

Бот поддержки — отдельный процесс со своим токеном:

```bat
scripts\support.cmd
```

Он принимает обращения и он же отправляет ответы админов. Пока он не запущен,
ответы висят в очереди — это видно в переписке. Отзывы в канал публикует основной
бот: отправлять в Telegram может только процесс бота, у админки нет транспорта
до `api.telegram.org` через прокси.

Проверить бота без сети (Telegram не нужен, пишет в отдельную базу `data/smoke.db`):

```bat
.venv\Scripts\python.exe -m app.tools.bot_smoke
```

Прогон скармливает боту настоящие апдейты через заглушку транспорта и печатает,
что бот ответил: тексты, кнопки, реакцию на выключенные разделы и ограничения.
LZT Market тоже подменён заглушкой, поэтому покупка, выдача кода входа, возврат
денег и «лот ушёл раньше» проверяются целиком — без сети и без денег. Платёжные
сервисы подменены так же: счёт, «Проверить оплату», отмена, молчащий провайдер,
фоновый опрос и процент пригласившему проходят настоящим кодом. Заодно проходят
своя сумма пополнения, ключ сессии в карточке заказа и отзыв со звёздами.

Для очистки аккаунта покупателю не нужны `TELEGRAM_API_ID` и
`TELEGRAM_API_HASH`: сервер использует встроенную публичную идентичность
клиента, а авторизация берётся из Auth Key и DC ID конкретного заказа. При
установке зависимостей нужен `Telethon==1.42.0`. Если сборщик `pyaes` на
Python 3.14 остановится, используйте Python 3.12 или 3.13 для окружения бота.

## Запуск админки

```bat
scripts\admin.cmd
```

http://127.0.0.1:8080 — логин и пароль из `ADMIN_LOGIN` / `ADMIN_PASSWORD` в `.env`.
Первый админ создаётся автоматически при первом старте, если в базе админов нет.
Роли разделены явно: `owner` имеет полный доступ, `admin` — рабочие разделы,
`support` — только очередь поддержки и переписку. Неизвестная роль получает `403`.
В production обязательно задайте собственный `ADMIN_SECRET`.

## Запуск сайта и Mini App

```bat
scripts\web.cmd
```

Локально сайт работает на `http://127.0.0.1:8081`. Обычный сайт открывается с
приветственной страницы и поддерживает вход через Telegram, Google или гостевой
режим. Гость видит каталог, поддержку и профиль, но покупка и переписка доступны
только после входа. Маршрут `/app` предназначен для Telegram Mini App: он не
показывает приветствие и форму входа, а проверяет подписанный `initData` Telegram.

Сайт и бот используют одну базу и общий слой сервисов: баланс, каталог, покупка,
выдача кода, гарантийная замена, история заказов и поддержка не дублируются.
Проверить всё без внешней сети:

```bat
.venv\Scripts\python.exe -m app.tools.web_smoke
```

Для публичного адреса задайте `WEB_BASE_URL=https://antarctic.cfd`,
`WEBAPP_BASE_URL=https://antarctic.cfd/app` и непредсказуемый `WEB_SECRET`. Для
Telegram Login Widget укажите `antarctic.cfd` через BotFather `/setdomain`. Для
Google OAuth создайте Web application в Google Cloud Console, добавьте redirect
URI `https://antarctic.cfd/auth/google/callback` и заполните `GOOGLE_CLIENT_ID` и
`GOOGLE_CLIENT_SECRET`.

### Публикация на Cloudflare Tunnel (Windows)

Для локального компьютера админка и магазин публикуются без открытия локальных
портов в интернет: `https://dabbackwood.cfd` ведёт на админку, а
`https://antarctic.cfd` — на сайт и Mini App.

1. Скачайте официальный `cloudflared-windows-amd64.exe` и положите его как
   `tools\cloudflared.exe`.
2. Добавьте обе зоны в один Cloudflare-аккаунт и назначьте доменам выданные NS.
   Затем выполните `tools\cloudflared.exe tunnel login`.
3. В DNS каждой зоны создайте проксируемую запись `CNAME`: имя `@`, цель
   `9a5036eb-ca98-483c-aca6-ab6d5dc8a3c5.cfargotunnel.com`.
4. Запустите `scripts\tunnel.cmd`. Он проверит порты 8080 и 8081, запустит
   локальные приложения и подключит туннель.

### Публикация на хостинге

Хостинг должен запускать только одну команду:

```text
python run.py
```

Если хостинг выдаёт переменную `PORT`, `run.py` использует её автоматически.
Если переменной нет, оставьте `HOSTED_MODE=auto`: на Linux с `ENV=prod` режим
хостинга определится автоматически. Явно задайте `HOSTED_MODE=true` только если
панель не выставляет ни `PORT`, ни production-окружение. Для `gunicorn run:app`
конфигурация проекта использует `PORT`, который выдал хостинг, а при его
отсутствии — внутренний порт `80`. Приложение слушает `0.0.0.0`, а не localhost.
Порт вроде `40002` в адресе `http://IP:40002` у некоторых хостингов является
внешним пробросом и не должен автоматически подставляться в Tunnel origin.
Магазин и админка работают через один публичный порт и выбираются по домену:

* `antarctic.cfd` → магазин и Mini App;
* `dabbackwood.cfd` → админ-панель.

В панели хостинга добавьте оба домена к одному Web Service. DNS-записи должны
указывать на адрес/hostname, который выдал хостинг. Не создавайте отдельные
процессы для `uvicorn`, `app.web.main`, `app.admin.main` или ботов.

Если Custom Domains у хостинга нет, создайте Cloudflare Tunnel в Zero Trust,
добавьте его token в переменную `CLOUDFLARED_TUNNEL_TOKEN`. На Linux-хостинге
`run.py` автоматически скачает официальный `cloudflared` нужной архитектуры и
запустит его рядом с приложением. Для хостинга, который выдал только
`http://93.123.84.239:40002`, настройте Tunnel так:

1. В Cloudflare Zero Trust → Networks → Tunnels создайте Tunnel.
2. В его Public Hostnames добавьте `antarctic.cfd` и `dabbackwood.cfd`.
3. Для обоих hostname укажите Service `HTTP` и URL
   `http://127.0.0.1:80` (или значение `PORT`, если хостинг явно задал его
   как внутренний порт приложения). Внешний порт из выданной ссылки хостинга
   сюда не подставляется.
4. Скопируйте token коннектора в переменную хостинга
   `CLOUDFLARED_TUNNEL_TOKEN`.
5. В Cloudflare DNS удалите старые A/CNAME-записи для этих доменов. После
   добавления Public Hostnames Cloudflare сам создаст CNAME на `cfargotunnel.com`.

В этом варианте Gunicorn слушает `0.0.0.0:80` либо значение `PORT`, а tunnel
запускается прямо на хостинге. Ваш компьютер и локальный `scripts\\tunnel.cmd`
больше не нужны.

Проверьте после запуска:

```text
http://IP:PORT/healthz
https://antarctic.cfd/healthz
https://dabbackwood.cfd/healthz
```

Для постоянной базы задайте `DATABASE_URL` PostgreSQL и подключите volume для
`/app/data`, если хостинг предоставляет диски. Локальный `data/shop.db` не
переносится на сервер автоматически.

Все части проекта также можно запустить одним Python-файлом. На Windows значение
`HOSTED_MODE=auto` означает локальный запуск: порты 8080/8081 и именованный
Cloudflare Tunnel из `.cloudflared/dabbackwood-config.yml`. В этом режиме
проверки production-секретов не мешают локальному старту:

```bat
python run.py
```

В локальном режиме команда поднимает основной бот, бот поддержки, админку, сайт
и Cloudflare Tunnel. Для сервера без
туннеля используйте `python run.py --no-tunnel`; перед первым запуском новой
версии с миграциями — `python run.py --migrate`.

Скрипт использует именованный туннель `dabbackwood-admin` и направляет домены на
порты 8080 и 8081 соответственно. DNS создаётся вручную, потому что один
origin-сертификат `cloudflared` не умеет безопасно выбрать сразу две корневые зоны.
Если Cloudflare пишет про `antarctic.cfd.dabbackwood.cfd`, новый домен не добавлен
отдельной зоной. Удалите эту ошибочную DNS-запись, добавьте `antarctic.cfd` через
**Add a domain**, смените NS у регистратора и дождитесь статуса **Active**.

Сменить пароль или добавить сотрудника:

```bat
.venv\Scripts\python.exe -m app.tools.create_admin support Пароль123 --role support
```

Проверить админку без браузера (своя база `data/smoke_admin.db`, маркет подменён):

```bat
.venv\Scripts\python.exe -m app.tools.admin_smoke
```

Проверить очередь рассылок без Telegram (своя база `data/smoke_broadcast.db`):

```powershell
.venv\Scripts\python.exe -m app.tools.broadcast_smoke
```

В админке раздел «Рассылки» создаёт черновик, фиксирует аудиторию при запуске и
отправляет её через очередь основного бота. Доступны аудитории всех клиентов,
пополнявших баланс, покупателей и Telegram Premium; забаненные исключаются.
Поддерживаются HTML Telegram, ссылки, `<tg-emoji>`, inline-кнопки и картинки
(изображение нормализуется в JPEG). Отправка ограничивается скоростью Telegram,
временные сетевые ошибки возвращают получателя в очередь, а после перезапуска
зависшие claims восстанавливаются. Страница рассылки показывает доставленные,
ошибочные и заблокированные чаты; отправку можно отменить.

Прогон заходит логином и паролем, открывает все разделы (включая отзывы и
поддержку) и нажимает все действия (код, сброс, возврат, обновление наличия,
правка страны, удаление позиции, обход стран маркета, сверка и ручное зачисление
счётов, баланс, бан, настройки), печатает заголовок экрана с сообщением после
каждого шага и в конце — что осталось в базе, включая сверку «сумма движений =
остаток». Шаги, где отказ и есть правильный ответ (неверный пароль, занятый код
позиции), помечены `ждали`; в «проблемы» попадает только неожиданное.

## Каталог и покупка

Цену покупателю задаёт админ — по стране, фиксированную. Лот бот подбирает сам:
берёт из `/telegram` самые дешёвые активные лоты в пределах **лимита закупки** и
покупает первый, который дался. Маржа = цена минус лимит, она видна в списке
каталога. Если под лимит ничего нет — «нет в наличии», покупка не предлагается.

Порядок покупки: заказ и списание пишутся в базу **до** обращения к маркету,
поэтому деньги не могут уйти дважды. Подтверждённая неудача (лот уже продан,
поиск не удался) автоматически возвращает деньги. Если ответ потерялся после
`fast-buy` или маркет пока не отдал данные входа, заказ остаётся на перепроверке:
возврат в этот момент мог бы потерять уже купленный лот. Данные входа приходят
от маркета уже после оплаты лота, код входа
клиент запрашивает кнопкой — **12 часов после покупки** (`shop.code_hours` в
настройках, `0` — без срока). Код приходит отдельным сообщением, а не правкой
карточки: иначе следующее нажатие затрёт его, пока человек вводит цифры в
Telegram. После срока код выдаёт только поддержка — из карточки заказа в админке.

Маркет отдаёт ключ сессии в полях `loginData.login` / `loginData.password`, но
это **не логин и не пароль**: там auth key в hex и номер дата-центра. В боте они
спрятаны за кнопкой «Ключ сессии». При подтверждении кнопки «Очистить аккаунт»
бот собирает из них временную Telethon `StringSession`, подключается без
создания `.session`-файла и удаляет личные диалоги/контакты, а из чужих групп и
каналов выходит. Созданные аккаунтом сообщества намеренно пропускаются и
попадают в отчёт, чтобы не затронуть других участников.

## Страны маркета

«Каталог → Страны маркета» показывает, что вообще есть на LZT: сколько лотов по
стране, минимальная цена, средняя по самым дешёвым лотам и максимальная в выборке.
По этой таблице страна и заводится в витрину: кнопка «Добавить» открывает форму с
уже подставленным кодом, названием и лимитом закупки от средней цены.

Перечня стран в API нет, поэтому цифры собирает обход: один запрос на страну,
пауза между запросами, всё это фоновой задачей — на полный список уходит около
минуты. Каждая страна пишется своей короткой транзакцией: в sqlite писатель
один, и одна транзакция на весь обход закрывала бы базу для бота и остальной
админки. Результат лежит в таблице `market_stats`, страница читает базу, а не
маркет. Обойти можно все страны или только те, что уже в каталоге; одну страну
проверяют кнопкой в строке.

Удаление позиции — через страницу подтверждения. Заказы остаются в истории:
название, код и цену они хранят своим снимком, ссылка на позицию обнуляется.

## Пополнение баланса

Порядок экранов: сумма → способ → счёт. Сумма спрашивается первой, потому что от
неё зависит доступность способа (у xRocket свой минимум в крипте), а лимиты
магазина от способа не зависят. Сумма едет в `callback_data` кнопок способов, а не
только в состоянии FSM: после перезапуска бота кнопка обязана работать.

Своя сумма принимается в любой момент, а не только пока бот её ждёт: сообщение из
одних цифр (можно «700 р», «1 500,50 ₽») в магазине номеров ничем другим быть не
может. Раньше сумма разбиралась только по состоянию FSM, а оно живёт в памяти
процесса и снимается после первого же экрана — набранное «500» после быстрой
кнопки или после перезапуска уезжало в «не понял».

| Способ | Как выставляется счёт |
|---|---|
| Crypto Bot | Счёт сразу в рублях (`currency_type=fiat`, `fiat=RUB`), крипту выбирает покупатель |
| xRocket | Фиата в API нет — счёт в `USDT` (настраивается), рубли пересчитываются по курсу Crypto Bot |
| Platega | Карта и СБП, пока не реализован |

Курс берётся у Crypto Bot (`getExchangeRates`, обновляется на их стороне) — своего
у xRocket нет, поэтому xRocket без `CRYPTOBOT_TOKEN` в списке способов не
показывается. Криптосумма округляется **вверх** и умножается на наценку
`topup.xrocket_markup` (по умолчанию 3%): xRocket берёт с магазина около 1.5%, и
без наценки магазин получил бы меньше, чем зачислил. Зачисляем всегда ту сумму в
рублях, которую человек ввёл, — её он видел, когда создавал счёт; курс,
криптосумма и ответ провайдера ложатся в `payments.raw` для сверки.

Об оплате узнаём **опросом** каждые 25 с: у Crypto Bot один запрос на все
ожидающие счёта, у xRocket — по счёту. Вебхуки оба провайдера умеют, и проверка
подписи для них уже написана (`check_signature` в обоих клиентах), но им нужен
публичный https-адрес, которого у магазина пока нет. Кнопка «Проверить оплату»
делает то же, что опрос, но по одному счёту. Зачисление идемпотентно: статус
переводится условным `UPDATE ... WHERE status='pending'`, кто первый — тот и
зачисляет, второй видит `rowcount 0`. Открытых счётов на человека — не больше трёх.

Процент пригласившему начисляется в момент зачисления, от суммы пополнения, с
округлением вниз; на один счёт — одна запись в `referral_earnings`.

Раздел «Платежи» в админке даёт фильтры по статусу, способу и поиск (внешний id,
номер счёта, tg_id, юзернейм), сумму зачисленного по фильтру и четыре действия:
сверить все ожидающие, проверить один счёт, снять счёт, зачислить вручную.
Ручное зачисление меняет баланс сразу, но сообщения в Telegram не отправляет:
админка живёт отдельным процессом и сессии бота у неё нет — клиент увидит деньги
в профиле.

Проверить связь с провайдерами:

```bat
.venv\Scripts\python.exe -m app.tools.pay_check me
.venv\Scripts\python.exe -m app.tools.pay_check rate --asset USDT
.venv\Scripts\python.exe -m app.tools.pay_check currencies
.venv\Scripts\python.exe -m app.tools.pay_check quote --amount 300
.venv\Scripts\python.exe -m app.tools.pay_check invoice --provider xrocket --amount 300
```

`quote` печатает, что увидит покупатель на эту сумму у каждого способа. `invoice`
создаёт настоящий счёт (денег это не списывает) и сразу снимает его, если не
передать `--keep`; в базу она не пишет.

## Отзывы

После выдачи кода в карточке заказа появляется «Оставить отзыв»: оценка 1–5, потом
текст или «без текста». Один отзыв на заказ. Сбор выключается в настройках
(`reviews.enabled`), канал задаётся там же — `reviews.channel_chat` (`@канал` или
id) и `reviews.channel_url` для ссылки клиенту. При `reviews.auto_publish` отзыв
уходит в канал сразу, иначе ждёт «Отзывы» в админке: одобрить или отклонить с
причиной.

Карточка в канале — картинка по шаблону: фон-фотография магазина, слева круглая
аватарка клиента, под ней ник со звёздочками (`ma***in`), справа сверху оценка
звёздами, ниже текст, справа внизу товар. Рисует Pillow (`app/services/review_card.py`),
готовый файл лежит в `data/reviews/review_<id>.png` и запоминается в отзыве —
повторная отправка берёт его, а не рисует заново.

Фон — `media/review_card_bg.jpg` (путь меняется ключом `reviews.card_bg`).
Загружается на странице «Отзывы» кнопкой «Загрузить фон»: файл перекодируется в
JPEG и обрезается по центру под 1280×520, так что годится широкая фотография.
Фона нет — карточка светлая, чёрным по F6F6F4. Цвет текста выбирается по средней
яркости фона, тёмное фото ровно притеняется, иначе на снегу белых букв не видно.
Звёзды рисуются многоугольником, а не символом `★`: в Arial и Liberation такого
глифа нет, вместо оценки уехали бы квадратики. Шрифт ищется в `media/fonts`, потом
среди системных (Arial, Liberation Sans, Arimo, DejaVu) — на странице отзывов
видно, какой взят; если системных с кириллицей нет, положите TTF в `media/fonts`.

Картинку можно выключить (`reviews.card_image`) — тогда, как раньше, уходит
аватарка клиента с подписью текстом, а без аватарки просто текст. Тот же путь
работает и если Pillow не установлен. Предпросмотр шаблона и карточка каждого
отзыва открываются в админке на странице «Отзывы».

Публикует бот, а не админка: у админки нет socks-транспорта до Telegram. Одобренный
отзыв кладётся в базу без `channel_message_id`, а фоновая задача бота
(`reviews.publish_loop`, раз в минуту) забирает такие и отправляет. Поэтому «Одобрено»
в панели значит «уйдёт в течение минуты», и это написано прямо на странице.

Тестовый отзыв отправляется из панели: на странице «Отзывы» блок «Тестовый отзыв
в канал» — ник, оценка, товар, текст. Он идёт тем же путём, что настоящий (статус
published, отправляет бот), поэтому в канале видно ровно то, что увидит покупатель,
и покупать номер для проверки не нужно. Клиента и заказа у такого отзыва нет
(`user_id IS NULL`), ник и товар берутся из своих колонок `author_name` и
`product_title`, аватарки нет — вместо неё круг с первой буквой. В списке он
помечен «тестовый» и только его можно удалить — через страницу подтверждения;
клиентские отзывы по-прежнему отклоняют, а не удаляют. Сообщение в канале
удаление сообщений в купленном аккаунте выполняется только из карточки заказа
после отдельного подтверждения клиента; админка по-прежнему не получает
Telegram-сессию и не может запускать эту операцию сама.

## Поддержка

Переписка живёт в отдельном боте (`SUPPORT_BOT_TOKEN`), в основном — только часы
работы (`support.hours`) и кнопка-ссылка. Первое сообщение открывает обращение и
получает автоответ (`support.auto_reply`, в него подставляются часы); дальше
сообщения падают в ту же ветку, пока её не закроют. Принимаются текст и фото.
Больше 10 сообщений подряд без ответа админа бот не берёт — просит подождать.

Ответ админа отправляет тоже бот, через базу: панель пишет строку в переписку, а
`support.delivery_loop` в боте поддержки раз в пять секунд забирает неотправленные
и шлёт клиенту. Состояние видно в колонке переписки: пусто — доставлено, «в
очереди» — бот ещё не забрал (или не запущен), «не дошло» — Telegram отказал
(например, клиент заблокировал бота), такие строки очередь не держат.

Фото из обращений видно только в боте поддержки: панель — отдельный процесс без
доступа к Telegram, файлы она открыть не может, в переписке стоит пометка о вложении.

## Проверка связи с LZT

```bat
.venv\Scripts\python.exe -m app.tools.lzt_check me
.venv\Scripts\python.exe -m app.tools.lzt_check countries --pmax 60
.venv\Scripts\python.exe -m app.tools.lzt_check search --country ID --pmax 30
```

Страна в API — ISO-код из двух букв **в верхнем регистре** (`ID`, `US`, `KZ`).
В нижнем регистре маркет молча отдаёт ноль лотов, поэтому клиент приводит регистр сам.
Готового перечня стран в API нет: `countries` проходит поиском по кандидатам из
[app/countries.py](app/countries.py) и печатает, где сколько лотов и от какой цены.
Российских номеров на маркете нет вообще.

## Деньги

Внутри всё в копейках (`int`). `float` на балансах и ценах не используется:
цены LZT приходят рублями с дробью и конвертируются через `app.money.rub_to_kop`.
Баланс пользователя всегда равен сумме его строк в `balance_tx`.

## Состояние проекта

Готовы: база, клиент LZT, бот с пятью разделами, каталог стран, страницы цен
маркета, покупка с подбором лота и выдачей кода входа, пополнение через Crypto Bot
и xRocket с начислением процента рефералам, отзывы (сбор, модерация и публикация
в канал), поддержка (второй бот и переписка в панели), админка (обзор, заказы,
клиенты, каталог, платежи, отзывы, поддержка, рассылки, настройки, логи).

Сайт и Mini App собраны в `app/web`; Platega для карты/СБП пока оставлена как
запланированный провайдер. Для production задайте непредсказуемые `ADMIN_SECRET`
и `WEB_SECRET`: пустые и дефолтные значения запрещены.

Бот, сайт и Mini App используют общий слой `app/services`, чтобы правила магазина
не расходились между интерфейсами.

## Справочник по маркету

Основной обязательный справочник интеграции —
[lolzteam-py: Market API sections](https://github.com/medovi40k/lolzteam-py#market-api-sections).
Для точных HTTP-полей дополнительно использован
[LOLZTEAM / Market.md](https://github.com/AS7RIDENIED/LOLZTEAM/blob/main/Documentation/Market.md#telegram):
поиск `GET /telegram` (границы цены — дробные числа, а не целые рубли; есть
`origin`/`not_origin`, `sb`/`nsb`, `order_by`, `page`), покупка
`POST /{item_id}/fast-buy`, код входа `GET /{item_id}/telegram-login-code`,
сброс сессий `POST /{item_id}/telegram-reset-authorizations`. Список допустимых
значений фильтров отдаёт `GET /telegram/params` — он же источник кодов стран
для поля «страна для LZT» в каталоге.
